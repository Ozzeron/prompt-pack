v0.1.8 - positioning patch (attention budget, "why not another prompt list")

Editorial release: no skill behaviour changes beyond an updated meta
skill description and opening paragraph. The pack's positioning
caught up with what the discipline actually does.

What v0.1.8 changes:

prompts/meta/token-discipline/SKILL.md (v0.1.0 -> v0.2.0):
- description rewritten from "Cross-cutting rules for spending
  context tokens wisely" to "Manage the agent's attention budget.
  Read what improves correctness; skip what adds noise."
- Opening paragraph reframed to lead with "Tokens are an attention
  budget, not a money budget." Explicit that the skill exists not
  to save the user money but because, even on unlimited budgets, a
  context window stuffed with low-signal files makes the model
  worse: it loses track of what matters, mixes patterns from
  unrelated code, and hallucinates with more confidence. Bigger
  context is not smarter context. Goal is "spend context where it
  buys reliability; do not spend it on noise."
- Behaviour rules below (hard-rules / soft-rules / sampling /
  weak-model adjustments) unchanged. Reframing is positional, not
  mechanical.

README.md:
- Opening section retitled "Why another prompt repo" -> "Why not
  another prompt list?" The first paragraph now states the position
  directly instead of asking the reader to derive it from bullets:
  this is not a prompt directory, it is a small opinionated
  discipline pack. Names the catalogue competitors explicitly
  (awesome-cursorrules, awesome-claude-code-subagents,
  awesome-copilot, awesome-agent-skills) before contrasting with
  "fewer skills, stronger behaviour".
- Why-section bullet 3 changed from "Token-disciplined ... context
  is money" to "Attention-disciplined, not token-cheap ... context
  is an attention budget ... bigger context is not smarter context".
- New "What this is not" subsection with four anti-claims that
  pre-empt typical first-glance objections from a Reddit / HN
  visitor: not a .cursorrules collection, not a vendor-specific
  bundle, not a benchmark or leaderboard, not exhaustive.
- New "Context discipline, not token cheapness" subsection
  explaining the lean / deeper-on-risky trade-off. Goal is better
  signal per token, not lower token usage.
- Status badge bumped to v0.1.8.

package.json:
- Version bumped to 0.1.8 to keep the release chain in sync.

What was deliberately NOT changed:

- File name token-discipline kept. Renaming to context-discipline
  would break Inherits links in 14 skills, the
  CODE_CREATING_SKILLS check in the linter, the installer profile
  lists, and the README profile-count cross-check. Cost is high;
  payoff (a slightly better word) is low. The inside framing of
  the file is what users read; the file name is a string they
  import by.

- No work-modes feature added (lean / balanced / deep). Proposed
  by external review, rejected as YAGNI for v0.1.x. No real user
  has asked for it. Adding it would require per-skill conditional
  behaviour, task-router awareness, linter validation, and config
  plumbing - half a day of architecture for positioning. Built
  under a concrete user need when one shows up, not before.

Quality gates after this release:
- 21/21 skills pass per-skill linter
- 4/4 cross-checks pass
- 3/3 CI jobs pass
